# VForge Complete Development Roadmap

> **Authoritative Sequence:** Master Prompt `Phase 0..15` reconciled with Architecture v1.2 §17 & §23–§32 (`ADR-0001`).  
> **Governance:** Every phase executes on its dedicated branch (`feature/phase-N-<slug>`), must pass all gates in [`QUALITY_GATES.md`](QUALITY_GATES.md), and feeds final readiness in [`RELEASE_ACCEPTANCE.md`](RELEASE_ACCEPTANCE.md).

---

## Capability Coverage Matrix (Architecture Groups A–J)

| Group | Capability Area | Mapped Phases |
|---|---|---|
| **A** | Orchestration, declarative scan plans, state machine, outbox, target leases, retries, timeouts, crash recovery | Phase 3 |
| **B** | Isolated Linux Runner Agent, mTLS, signed manifests, ephemeral container hardening, network egress/DNS-pinning boundary | Phase 4 |
| **C** | Scanner Adapter SDK & tool integrations (SAST, Secrets, SBOM, SCA, IaC, Web/API DAST, Network/TLS) | Phases 5, 6, 7 |
| **D** | Canonical findings, evidence-preserving correlation, fingerprinting, risk scoring, triage/retest/exception lifecycle | Phase 8 |
| **E** | Provenance-aware Threat Intelligence connectors (NVD, CVE, KEV, EPSS, OSV, GHSA, CWE, NIST, STIX/ATT&CK, gated enrichment) | Phase 9 |
| **F** | Controlled 4-stream / 10-channel Update Lifecycle (`candidate -> validated -> approved -> canary -> stable` + rollback) | Phase 10 |
| **G** | Rule & Skill Studio + Provider-Agnostic Runtime AI Gateway, retention/privacy gates & prompt-injection defenses | Phases 11, 12 |
| **H** | Professional reporting (HTML, PDF, JSON, SARIF) with provenance/coverage + notifications/integrations | Phase 8 (+ Ph 10/14 hooks) |
| **I** | Isolated vulnerable-app learning lab (Juice Shop, crAPI, WebGoat), resettable tracks & VForge self-scan | Phase 13 |
| **J** | Enterprise security hardening (OpenBao, AES-256-GCM envelope encryption, key/cert rotation, DR, fuzzing, observability, §32 release audit) + optional isolated AI red-teaming | Phases 14, 15 |
