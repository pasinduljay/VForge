# VForge Risk Register

Tracks architectural, security, operational, and delivery risks across the programme.

| Risk ID | Risk Description | Category | Probability | Impact | Mitigation | Owner | Status |
|---|---|---|---|---|---|---|---|
| RISK-01 | **Scanner compromise via untrusted target/code** (parser bug or malicious repo triggers RCE inside scanner) | Security | Low (Ph4) | Critical | Dedicated Runner Agent (`runner/`), TLS 1.3 mTLS gateway, Ed25519 signed `ExecutionManifest`, ephemeral `--read-only`, `--cap-drop=ALL`, `no-new-privileges`, seccomp allowlist, non-root `10001:10001`, zero Control Plane Docker socket; production deployment requires isolated Linux VM | Platform Security | Mitigated at runner/container layer (Ph4); production VM boundary deployment |
| RISK-02 | **Out-of-scope scanning or SSRF** (DNS rebinding, HTTP 302 redirect to metadata/internal IPs) | Security | Low | Critical | Phase 2 `vforge-scope` + OPA `scope.rego` + Ed25519 `scope_snapshots`; Phase 4 `ScopedEgressGateway` enforces allowlists, independent DNS, metadata/RFC1918 blocking, socket-connect IP pinning, and HTTP redirect revalidation; Phase 7 DAST RPS caps + safety auto-abort | Backend / Security | Mitigated at policy, egress gateway, and DAST health-monitor layers (Ph2, Ph4, Ph7) |
| RISK-03 | **Secret leakage in logs, errors, or Git** (`DATABASE_URL`, API tokens, Gitleaks findings) | Security | Low | High | `.gitignore` blocks `.env` & `.secrets/`; structured log + exception + metadata redaction tested; Gitleaks `--redact=100` + pre-persistence finding/log redaction verified (Ph5); PG/RMQ/Valkey least-privilege roles separated; `SecretProvider` forbids `.env` in prod; `auth_profiles` uses secret refs only (Ph7); OpenBao workload auth (`approle`/`kubernetes`/`jwt`/`oidc`), HTTPS enforcement, multi-KEK rotation & online DEK re-wrapping verified (Ph14) | Platform | Mitigated & verified (Ph0–Ph14) |
| RISK-04 | **Control-plane or scanner image drift / supply-chain compromise** | Supply Chain | Low | Critical | Pin all control-plane and scanner images by immutable `sha256` digest (`lifecycle/image-lock/phase0..7-images.json`) and block `:latest` tags/repos via schema + Pydantic + manifest checks; Renovate PRs with `automerge: false`; SBOM/SCA/IaC scans verified (Ph6); `update-controller`, fail-closed validation gates, canary/stable promotion, instant rollback, and Ed25519-signed dynamic runner allowlists verified (Ph10) | DevSecOps | Mitigated (Ph0–Ph7 lockfiles; Ph10 lifecycle controller & signed pins) |
| RISK-05 | **Active DAST side effects or target outage** (state mutation, accidental DoS) | Operational | Low | High | Exclusive PostgreSQL `scan_target_leases` (1 active job per `(asset_id, lease_risk_class)`) + `TargetHealthMonitor` baseline checks, periodic probes, and automatic tripwire abort on 5xx or latency spikes (Ph7) | Orchestration | Mitigated via exclusive target leases and target health auto-abort tripwires (Ph7) |
| RISK-06 | **PostgreSQL 18 volume misconfiguration** (`PGDATA` moved to `/var/lib/postgresql/18/docker`) | Operational | High (if overlooked) | Medium | Mount `postgres_data:/var/lib/postgresql` per official Postgres 18 docs; verified by Ph0 smoke test | Platform | Mitigated & verified (Ph0) |
| RISK-07 | **Next.js read-only container crash on `.next/cache`** | Operational | High (if overlooked) | Medium | Mount `tmpfs` at `/app/.next/cache` with non-root UID/GID; verified by Ph0 container smoke test | Frontend | Mitigated & verified (Ph0) |
| RISK-08 | **OPA scratch image lacks shell for Docker healthcheck** | Operational | High (if overlooked) | Low | Verify OPA health via API `/ready` endpoint & smoke script instead of broken in-container `CMD-SHELL` probe | Platform | Mitigated & verified (Ph0) |
| RISK-09 | **AI prompt injection or unsafe auto-generated rules** | Security / AI | Low (Ph12) | High | Phase 11 Rule & Skill Studio (`validators.py`, `ai_author.py`, `service.py`, `authz.rego`, `0012`) isolates untrusted snippets, blocks AI/self review & signing, requires positive/negative/near-miss fixtures & Ed25519 manifests; Phase 12 runtime AI gateway (`ai_gateway/{classification.py,rag.py,rule_author.py,service.py}`, `0013`) entity-escapes untrusted prompts & RAG chunks in balanced `<untrusted_data>`/`<untrusted_rag_context>` wrappers, blocks normalized privileged tools fail-closed in OPA `authz.rego`, and enforces SoD on human tool approval | AI / AppSec | Mitigated in Rule Studio & Runtime AI Gateway (Ph11–Ph12) |
| RISK-10 | **AI provider data retention violation** (e.g., `enterprise-30d-v1` 30-day retention without ZDR) | Privacy / Compliance | Low (Ph12) | High | Phase 12 AI Gateway (`0013`, `service.py`, `providers.py`) classifies & redacts secrets/PII pre-egress, enforces dual org-admin consent + operator acknowledgment on 30-day retained models (`enterprise-30d-v1`) and `restricted` payloads, supports org-wide `local_only_mode`, locks monthly token budgets with `FOR UPDATE`, pins hosted vendor domains + blocks SSRF/IMDS & cross-tenant `secret_ref`, and hard-blocks cross-tenant learning sharing | Governance | Mitigated & verified (Ph12) |
| RISK-11 | **False confidence from clean or partial scan** (unsupported language or failed stage) | Product Integrity | Low | High | Explicit `completed_with_errors`/`partial` states, polyglot `evaluate_coverage()` language coverage matrix on source snapshots and scan runs (`supported`/`partial`/`unsupported_languages`), UI banner & failed stages surfaced directly, honesty disclosure banner in HTML/PDF/JSON/SARIF reports (Ph5, Ph8) | Backend / UI | Mitigated in Phase 5 and Phase 8 multi-format reporting |
| RISK-12 | **Workstation resource exhaustion during local dev** (WSL2 + Compose + future scanners) | Operational | Medium | Medium | Memory & PID limits in `docker-compose.yml`; keep Phase 0 minimal; serialize heavy scans in later phases | Engineering | Mitigated for Ph0 |
| RISK-13 | **Unaudited risk exception expiration / SLA drift** (untracked vulnerability backlogs or unapproved risk acceptance) | Governance / Compliance | Low | High | Tenant-isolated `risk_exceptions` workflow with 2-person rule restricted to `security_lead`/`admin`/`owner`, explicit `expires_at` timestamps, automated SLA breach tracking (`check_and_update_sla_breaches`), and immutable append-only `finding_events` audit trail | Backend / Compliance | Mitigated in Phase 8 (`finding_events`, `risk_exceptions`, SLA monitor) |
| RISK-14 | **Threat feed outages or privacy leakage via third-party intel APIs** (false-negative findings on connector failure, sensitive binary/hash leaks) | Security / Privacy | Medium | High | Fail-closed connector contract preserves last-known-good snapshots and flags stale state (`is_stale: true`); never emits zero-findings on network/API failure; VirusTotal binary upload hard-blocked by default; Shodan scope verified against approved IP ranges (Ph9) | Platform / Threat Intel | Mitigated in Phase 9 (`gated.py`, `sync.py`, immutable `intel_snapshots`) |
| RISK-15 | **Vulnerable learning lab container exposure, egress pivoting, or abuse of real targets/credentials** | Security / Isolation | Low (Ph13) | High | Phase 13 lab (`infrastructure/lab/compose.lab.yaml`, `vforge/lab/safety.py`, `service.py`, `authz.rego`, `0014`) isolates lab containers in a separate Compose project on an `internal: true` bridge with loopback-only bindings, pinned `@sha256` digests, `tmpfs` disposable state, OPA fail-closed safe-action allowlisting, SSRF/IMDS/control-port target restrictions, epoch-bound disposable identities, and consent-gated progress resets | Platform / AppSec | Mitigated & verified (Ph13) |
| RISK-16 | **Autonomous AI red-team agent scope escape, self-approval, budget exhaustion, or hallucinated findings polluting reports** | Security / AI Red-Team | Low (Ph15) | Critical | Phase 15 sandbox (`infrastructure/redteam/compose.redteam.yaml`, `vforge/redteam/{policy,service}.py`, `authz.rego`, `0016`) attaches exclusively to `vforge-lab_lab_internal` (`internal: true`), blocks `shell:exec`/`docker`/`scope:modify`/`opa:modify`, enforces per-session human approval (`approved_by != requested_by`), freezes session budgets/targets via DB triggers, requires `cleanup_attested=True`, and records all AI outputs as `hypothesis` requiring independent human review (`reviewed_by != recorded_by`) | AI / Platform Security | Mitigated & verified (Ph15) |
| RISK-17 | **Destructive smoke-script downgrades against persistent DB or untested `pg_restore` archives** | Operational / DR | Low (Final Audit) | High | Removed live-DB `alembic downgrade` calls from smoke scripts (`VF-AUDIT-001`), added disposable-DB full migration chain verifier (`scripts/db/verify_migrations_disposable.ps1` testing `0001..0016 -> base -> 0016`), and upgraded `scripts/dr/backup_and_verify.ps1` (`VF-AUDIT-002`) to perform a full `pg_restore --exit-on-error` into an isolated disposable PostgreSQL container (`--internal` network + `--tmpfs`) verifying all 81 tables, 63 forced-RLS tables, 172 FKs, 35 triggers, and `vforge_app` read access | Platform / SRE | Mitigated & verified (Final Release Audit) |
